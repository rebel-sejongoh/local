전체 흐름

Spatial dataflow: pipelined region과 경계 현재 코드 기준 · DNC 하나의 shape

한 unit 안에서 일을 순서대로 하는 것(SPLU가 w 다음 x, TU가 prime 다음 compute)은 region을 끊지 않습니다. 메모리와 SYNC로 넘기는 SP·AB도 블록 단위 FIFO로 보고 region 안에 둡니다. region이 끊기는 곳은 다른 unit들을 거쳐 같은 unit으로 되돌아오는 의존이 생기는 곳 하나뿐입니다. 현재 코드에서는 store 1 뒤에 NCSU가 NCLU에 주는 credit이 그 의존을 만듭니다. R1은 16개 DNC가 모두 실행하고, R2는 root 4개(k = 0)만 실행합니다.

Region실행하는 DNCDNC 하나의 입력내부DNC 하나의 출력

전체—x [4,256] · w [256,64]—out [4,64] (4줄)

credit이 없다면 VU를 입력 두 개(TU, SPLU)를 받는 merge node로 보고 R1과 R2를 한 region으로 합칠 수 있습니다. 그래도 R2의 실제 입력은 leaf의 R1이 끝나야 생기므로 시간상 이득은 root R1의 꼬리 정도입니다. credit이 SP gather 영역을 다시 쓰는 것 등 다른 이유로 필요한지는 확인하지 않았습니다.

Reduction 요약 mcc 현재 방식 · star reduce

  1. Group: M shard 4 × K reduce 4라서 d = 4m + k입니다. 같은 m의 DNC 4개가 한 group이고 k = 0이 root입니다. root가 leaf 전부를 한 단계로 모읍니다.
  2. 모든 DNC: 자기 partial x[m, 64k:+64] @ w[64k:+64, :]을 4행 tile로 계산합니다(행 0만 실제, 1–3 padding). VU에 누적하고 SPSU가 SP에 저장합니다.
  3. leaf: 행 0을 SHM slot에 쓰고(STSU), root와 MESYNC를 주고받습니다. put으로 "준비됨"을 알리고, get으로 "가져갔음"을 기다립니다.
  4. root: leaf를 1, 2, 3 순서로 처리합니다. 준비됨을 받고(MESYNC get), slot을 SP로 load하고(LDMU), SPLU에 신호를 주고, leaf를 풀어 줍니다(MESYNC put). SPLU는 그 partial부터 시작하는 4줄 창을 VU로 보내고, VU는 자기 partial이 든 acc에 더합니다. SPSU는 같은 SP 4줄을 매번 덮어씁니다.
  5. 마무리: 마지막 단계 뒤 root의 NCSU가 SP 행 0(out[m, :])을 SHM에 씁니다. leaf는 출력을 쓰지 않습니다. 16개 DNC 전원이 cluster barrier로 끝납니다.

DNC j.NCLU → DNC 0.NCLUleaf NCLU MESYNC {get, put, dnc0, nclu}의 putroot NCLU MESYNC {dir.get=1, dnc0..7, nclu}
DNC 0.NCLU → DNC j.NCLUroot NCLU MESYNC {dir.put=1, dnc0..7, nclu}leaf NCLU MESYNC {get, put, dnc0, nclu}의 get

같은 문자열 MESYNC {dir.get=1, dir.put=1, sync_mask.dnc0=1, sync_mask.nclu=1}이 leaf의 NCSU(gather handshake)와 NCLU(cluster barrier) 두 곳에 있습니다. 어느 unit에서 실행하느냐에 따라 채널이 다릅니다. 채널은 (보내는 DNC·unit → 받는 DNC·unit)마다 따로라서, put은 상대 쪽 카운터를 +1 하고 get은 자기 쪽 카운터가 0보다 커질 때까지 기다렸다가 −1 합니다(PrecSim 모델 기준, ISA 문서의 MESYNC 페이지는 아직 TODO).

Root reduce timeline DNC 0 · NCLU · SPLU · VU · SPSU · NCSU

각 unit은 동시에 돌고, 아래 순서는 SYNC / MESYNC / FIFO가 강제하는 인과 순서입니다. leaf DNC는 A, B를 한 뒤 C의 "leaf" 줄로 자기 partial을 내보내고 E에 참여합니다.

── A. 입력 준비 ─────────────────────────────────────────────────────────────────────────
NCLU  LDMU src0=SAR0, src1=SBR0, src2=CAR0, src3=CBR0 {be=1}  ×2      w → SP 0x3d8..0x417
NCLU  SYNC {dir.put=1, lsync_mask.splu0=1}
SPLU  SYNC {dir.get=1, lsync_mask.nclu=1} ; LDU consumer=XVU, src0=LRF0, … ×64   w → XVU → TU north
NCLU  LDMU src0=SAR12, … {burst=1} ; SYNC put → splu0                 x → SP 0x418
SPLU  LDU consumer=XVU, src0=LRF2, src1=LRF10 {burst=1, burst_size=4}  SP 0x418..0x41b → ABSU

── B. 자기 partial ──────────────────────────────────────────────────────────────────────
VU    FMA lrf_tgt=LRF4, src0=FIFO_TU, src1=CONST4, src2=LRF4 {…}      acc[t] := 0 + S_7[t]
VU    FMA sp_tgt=RESULT, src0=LRF4, src1=CONST4, src2=CONST0 {…}      store 1
SPSU  STU producer=VU, … {burst_size=4} ; SYNC {dir.put=1, lsync_mask.ncsu=1}   → SP 0x419..0x41c
NCSU  SYNC {dir.get=1, lsync_mask.spsu0=1} ; SYNC {dir.put=1, lsync_mask.nclu=1}  credit: gather 시작

── C. 형제 gather, j = 1, 2, 3 ──────────────────────────────────────────────────────────
leaf  NCSU STSU … ; MESYNC {dir.get=1, dir.put=1, sync_mask.dnc0=1, sync_mask.nclu=1}
                                                                     DNC j: SP 0x419 → SHM 0x113+3m+j, root에 알림
        put: 채널 (DNC j.NCSU → DNC 0.NCLU) +1  ⇒ ① 아래 "leaf j 준비됨" get이 소비
        get: 채널 (DNC 0.NCLU → DNC j.NCSU) 대기 ⇐ ② 아래 "leaf j 해제" put이 +1
NCLU  SYNC {dir.get=1, lsync_mask.ncsu=1}                            credit (j = 1 전에 한 번)
NCLU  MESYNC {dir.get=1, sync_mask.dncj=1, sync_mask.ncsu=1}          ① leaf j 준비됨 (leaf의 put 소비)
NCLU  LDMU src0=SAR4, … {burst=1} ; SYNC put → splu0                 SHM 0x113+3m+j → SP 0x420+j
NCLU  MESYNC {dir.put=1, sync_mask.dncj=1, sync_mask.ncsu=1}          ② leaf j 해제 (leaf의 get을 풀어 줌)
SPLU  SYNC get ← nclu ; LDU consumer=VU, src0=LRF11, … {burst_size=4} ; MODLRFIMM −3줄

NCSU  SYNC get ← spsu0 (store 4) ; STSU src0=SAR11, … ; SYNC put → nclu    SP 0x419 → SHM 0x110+m
NCLU  SYNC {dir.get=1, lsync_mask.ncsu=1}

── E. 종료 ──────────────────────────────────────────────────────────────────────────────
NCLU ⇄ NCSU  SYNC {dir.get=1, dir.put=1, …}                          DNC 안의 fence
NCLU  MESYNC get dnc0..7 ; MESYNC get+put dnc8 ; MESYNC put dnc0..7   cluster barrier
leaf  NCLU MESYNC {dir.get=1, dir.put=1, sync_mask.dnc0=1, sync_mask.nclu=1}
        put: 채널 (DNC j.NCLU → DNC 0.NCLU) +1  ⇒ root의 "MESYNC get dnc0..7"이 소비
        get: 채널 (DNC 0.NCLU → DNC j.NCLU) 대기 ⇐ root의 "MESYNC put dnc0..7"이 +1

sync_mask.dncj는 j에 따라 dnc1, dnc2, dnc3입니다. leaf (m, j)가 쓰는 주소 0x113 + 3m + j는 이 이미지의 DNC 0·1(0x114, root가 읽는 0x114–0x116)과, 같은 kernel을 최신 mcc로 빌드한 16개 이미지 전체에서 확인한 규칙(그룹마다 3줄씩, 시작 주소만 다름)에서 나온 것입니다.
